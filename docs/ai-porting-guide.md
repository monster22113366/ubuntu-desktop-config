# AI 移植与维护指南

## 1. 工程定位

本工程用于管理 Ubuntu 24.04 桌面及开发环境配置。

本工程主要面向 AI Agent（Codex、ChatGPT 等），由 AI 阅读、分析、修改和维护配置。

用户负责提出需求、审阅方案和确认修改。

AI 应优先理解现有工程，不要擅自重构或引入复杂架构。

## 2. 接手工程后的工作

首次接手工程时：

1. 阅读 README.md 和 INSTALL.md。
2. 阅读 docs/architecture.md 和 docs/customization.md。
3. 检查 profiles/ 中的硬件参数和用户偏好。
4. 阅读与当前任务相关的软件模块。
5. 检查目标电脑的操作系统、硬件和软件版本。
6. 对比工程配置与目标设备的实际情况。
7. 给出修改方案，确认后再实施。

不要在尚未理解工程结构时直接批量覆盖配置。

## 3. 硬件适配

重点检查：

- CPU、GPU 和显卡驱动。
- 显示器数量、名称、分辨率、刷新率、排列和缩放。
- 网络接口。
- 音频设备。
- 电池和背光设备。
- 输入设备。
- 目标软件及其版本。

优先使用 Linux 标准接口。

对于不同设备确实需要修改的参数，优先使用 Hardware Profile 提供的配置入口。

不要求自动检测所有硬件。

## 4. 配置修改

修改前：

1. 阅读完整的相关配置文件。
2. 确认参数的实际作用。
3. 检查是否存在其他模块的关联配置。
4. 备份需要修改的现有配置。

修改时：

1. 优先修改现有参数。
2. 尽量复用已有模块。
3. 保持软件原生配置格式。
4. 不随意改变目录结构。
5. 不引入没有实际必要的依赖。
6. 不覆盖用户已有的个性化配置。

## 5. 验证要求

每次修改后：

1. 执行对应的语法或配置检查。
2. 检查运行时日志。
3. 在适当条件下进行实际运行验证。
4. 明确告知用户哪些项目已经验证，哪些尚未验证。

配置解析成功不等于功能正常。

涉及桌面会话、显示器和显卡的修改时，优先考虑安全回滚方案。

## 6. 移植到新电脑

迁移时不要直接假设目标设备与原设备相同。

先检查硬件和软件环境，再修改 Hardware Profile 及必要的模块配置。

尽可能保留通用模块，只修改设备差异和用户明确提出的偏好。

## 7. 安全与维护

- 不删除未经确认的用户配置。
- 不擅自修改系统级配置。
- 不将密码、Token、代理订阅等敏感信息提交到 Git。
- 不执行来源不明的安装脚本。
- 不在没有备份的情况下进行大规模修改。
- 遇到不确定的 API 或配置选项时，先检查当前软件版本对应的文档。

## 8. 工作原则

本工程遵循高内聚、低耦合原则。

优先选择简单、直接、容易维护的实现。

不要为了追求通用性而过度自动化，也不要为了未来可能出现的需求提前设计复杂框架。

所有修改都应服务于用户当前的实际需求。
